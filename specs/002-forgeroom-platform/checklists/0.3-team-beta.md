# 0.3 team-beta release checklist

## Workflow integrity

- [ ] All required P2 tasks and all earlier release regressions are `done`.
- [ ] Workflow versions pin owner, inputs, outputs, skills, schemas, grants, approvals, budgets, failure policy and destination.
- [ ] Schedules pass zone/DST/misfire/overlap/failover tests.
- [ ] Webhook/provider triggers pass signature, replay, rotation, size and loop tests.
- [ ] Durable execution passes crash, duplicate, retry, timeout, dead-letter, cancellation and reconciliation tests.
- [ ] Cross-channel handoff transfers only a granted bounded context envelope with hop/loop limits.
- [ ] Background effects use the canonical proposal/approval/action gateway.

## Team and ecosystem

- [ ] Approver groups, delegation and workspace inbox enforce eligibility, quorum and separation.
- [ ] Per-human connections remain exact-account pinned and revocable.
- [ ] Opt-in external notifications, workflow recipient routing, quiet hours and fixed security escalation pass privacy/retry tests.
- [ ] Extension SDK capability, compatibility, install/revoke and malicious-package tests pass.
- [ ] Team-beta browser and security/recovery suites pass three times from reset.

## Trial gate

- [ ] Three design partners run production-like scheduled workflows for 30 days.
- [ ] Every trigger is attributable, deduplicated, budgeted, inspectable, stoppable and notified.
- [ ] Every public comparison is row-scoped in `parity.md`, dated, source-backed and linked to released-artifact tests/user docs/trial evidence; computer use is explicitly excluded.
- [ ] No unresolved critical/high authorization, duplicate-effect or data-loss issue remains.
- [ ] P2-503 contains release provenance, trial report and gate approval.
